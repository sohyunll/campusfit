## 월요일 — 코드 이해 + Git/GitHub 개념

### 1. `client/src/pages/Main.jsx` 뜯어보기

```jsx
const [status, setStatus] = useState("연결 확인 중...");
```
- **state**: "지금 값을 기억하는 상자". `status`는 지금 값, `setStatus`는 그 값을 바꾸는 함수.
- `setStatus(...)`를 부르는 순간 화면이 자동으로 다시 그려진다.

```jsx
useEffect(() => { ... }, []);
```
- 화면이 처음 뜰 때 **딱 한 번** 실행되는 코드. 뒤에 붙은 빈 배열 `[]`이 "한 번만"이라는 뜻.

```jsx
api.health().then(() => setStatus("서버 연결됨")).catch(() => setStatus("서버 연결 실패"));
```
- 서버에 요청을 보내고, **성공하면 `.then()`, 실패하면 `.catch()`**가 실행됨 — 비동기 처리의 기본형.

### 2. `design/prototype.html` 필터 패널 뜯어보기

```html
<input type="radio" name="f-univ" id="f-univ-nat">
<label class="option inline" for="f-univ-nat">국립대</label>
```
```css
#f-univ-nat:checked ~ .filter-body label[for="f-univ-nat"] {
  background: var(--bulb); color: #fff;
}
```
- `<label for="...">`를 클릭하면, 같은 `id`를 가진 `<input>`이 눌린 것처럼 동작 — JS 없이 순수 HTML/CSS로 클릭 반응 만드는 트릭.
- `:checked` = "체크된 상태일 때"라는 CSS 조건. `~` = 형제 선택자.
- **내일 할 일**: 이 CSS 트릭 대신, `useState`로 "지금 뭐가 선택됐는지" 저장하고 `onClick`으로 바꾸는 방식으로 React에서 똑같은 동작을 만든다.

### 3. Git 흐름

```
파일 수정 → git add .(대기줄에 올림) → git commit(진짜 저장) → git push(GitHub 업로드)
```
- **Working Directory**: 지금 눈에 보이는 실제 파일들
- **Staging Area**: `git add`로 올려놓은 "이번에 저장할 것들" 대기 줄
- **Repository(.git)**: `git commit`으로 영구 저장되는 곳
- **커밋(commit)**: 파일 하나가 아니라 "하나의 작업 단위" 스냅샷
- **브랜치(branch)**: 같은 저장소 안에서 작업을 갈라 동시에 진행하는 갈래 (`main` vs `N010_권소현`)
- **HEAD**: 지금 내가 어느 브랜치·커밋에 서 있는지 가리키는 책갈피

### 4. 용어 정리

- **JavaScript**: 웹의 "행동" 담당 언어 (HTML=뼈대, CSS=옷, JS=동작)
- **React**: JS로 화면을 만들 때 state가 바뀌면 자동으로 다시 그려주는 도구. 컴포넌트 단위로 화면을 나눔
- **Plan mode**: Claude Code가 코드를 바로 바꾸지 않고, 계획을 먼저 보여준 뒤 승인받고 실행하는 모드
